Detailed Description

One CONTRACT.md §27.6.1 role binding (contract 1.51): a groups[].roles[] or service_accounts[].roles[] entry.

Either shape the contract specifies —

  • a bare role key ({.role = "editor"}): no resource, so no inheritance question, the binding as every SDK had it before 1.51; or
  • the resource-scoped shape ({.role = "editor", .resource = "docs-root", .inherit = false}): resource and inherit are both optional, and inherit reaches the wire ONLY as false — an engaged true is refused client-side (§27.6.1: "An SDK MUST NOT send <tt>inherit: true</tt> explicitly, so that an inheritable binding's body stays byte-for-byte a pre-1.51 body").

is this one struct; a bare role key is simply resource/inherit both disengaged.
