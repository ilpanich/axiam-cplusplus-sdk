# A hand-rolled AXIAM Reactor — CONTRACT.md §22

**This sample is NON-NORMATIVE. This SDK ships no reactor runtime.**

[`CONTRACT.md`](../../CONTRACT.md) **§22.11** defers the `reactor_serve` helper on
Swift, C and C++ for the same reason §8 has never listed those targets among the
SDKs that speak AMQP: there is no vendorable AMQP client this project is willing
to put on embedded and mobile deployments. Nothing in this directory is part of
the library, nothing here is installed, and no header under `include/axiam/`
gained a reactor API.

**What §22.11 does say is that the absence of a helper changes nothing about the
protocol:**

> §22.1–§22.8 is a wire protocol, and a wire protocol does not become optional
> because no helper wraps it. An integrator hand-rolling a reactor on these
> runtimes against a third-party AMQP client MUST satisfy every normative rule in
> those subsections […] The §22.13 vectors are the conformance surface, and they
> need no SDK to run against.

and about this sample specifically:

> It is an example, not a contract surface: this section governs, and the sample
> conforms to it or is wrong.

So that last sentence is checkable rather than aspirational,
[`reactor.cpp`](reactor.cpp) runs the committed **§22.13 reference vectors** —
generated by the AXIAM server's own sign path, and vendored here as
[`reactor_v2_reference_vectors.json`](reactor_v2_reference_vectors.json) — in
both directions and exits non-zero if a single byte differs.

## What it demonstrates

| Rule | Where |
|---|---|
| §22.2 — the MAC runs in **both** directions under one tenant subkey | `hmac_sha256_hex`, `verify_event`, `build_reply` |
| §22.2 — `hmac_signature` is serialized as **`null`** inside the signed bytes, *not* omitted as §8's own two message types omit it | `canonical_event`, `canonical_reply` |
| §22.2 — declared field order, and the omission of `reason`/`patch` when absent and `require_mfa` when false | `canonical_reply` |
| §22.3 — key version, then MAC, then freshness, then nonce; **only then** decode the payload | `verify_event` |
| §22.3 — freshness is two-sided; a future timestamp is not "extra fresh" | `verify_event` |
| §22.4 — a patch is sent **unfiltered**; `allow` + `patch` has no representation | `Answer` |
| §22.5 — the registry and its namespace-prefix allow-list rule | `patch_field_allowed` |
| §22.8 — the **strictest** default failure policy wins, in either array order | `default_failure_policy` |
| §22.7 — the hot-path decision operations appear in no list and no comment | (by absence) |
| §22.1 — the transport seam carries no declare or bind method | `ReactorTransport` |

## What you still have to supply

**The AMQP client.** That is the one piece this project will not pick for you,
and it is the whole reason §22.11 defers the runtime. `rabbitmq-c`,
`SimpleAmqpClient` and `AMQP-CPP` are all commonly used; whichever you choose:

- **§8b** — connect over `amqps://` with a supplied CA bundle. No
  verification-skip switch, no plaintext fallback. HMAC does not substitute for
  TLS and TLS does not substitute for HMAC.
- **§22.1** — consume `axiam.reactor.q.<tenant_id>.<reactor_id>`, the queue the
  **server** declared, with manual acknowledgement, and **declare nothing**. No
  exchange, no queue, no binding. A reactor that can bind is a reactor that can
  bind itself to `*.token.pre_issue` and read another tenant's issuance events.
- **§22.1** — publish the reply to the delivery's `reply_to` queue through the
  default exchange, echoing its `correlation_id` property. What the server
  authenticates is the `correlation_id` *inside the signed reply body*: copy it
  from the event body, because copying it only into the AMQP property produces a
  reply the server discards.
- **§22.8** — on any failure of your own (a handler that throws, a body you
  cannot decode, a window that has closed) publish **nothing**. The
  registration's `failure_policy` decides, and a synthesized `allow` would
  override the operator's `fail_closed` from inside your own process.

## Build and run

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DAXIAM_BUILD_EXAMPLES=ON
cmake --build build -j
./build/examples/axiam_example_reactor
```

It needs no broker, no server and no network: it verifies the committed vectors,
then prints the reply it would publish for one `token.pre_issue` dispatch.
