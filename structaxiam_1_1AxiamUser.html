Detailed Description

Authenticated identity injected by the §10 guard into the request context.

roles and scope come from two different claims and never stand in for each other (§11.2 rule 11). roles is the token's roles claim; it is present only when the application requested the roles scope (§11.2 rule 11(f)). scope is the token's space-separated scope string.

The members after roles are appended, so an aggregate initialiser that names only {user_id, tenant_id, roles} keeps working: it describes an identity whose roles claim was present.

◆ roles_claim_present

bool axiam::AxiamUser::roles_claim_present = true

Whether the token carried a well-formed roles claim (a JSON array of strings).

false keeps "the token says nothing about roles" (absent, or a claim that is not an array of strings) apart from roles_claim_present && roles.empty() ("the token says the holder has none"): the first means ask for the roles scope, the second means the user holds no role (§11.2 rule 11(b)). Both fail every require_role. TokenAuthenticator sets it; it is true for a hand-built identity, which lists its roles itself.
