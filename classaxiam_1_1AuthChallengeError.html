Detailed Description

An authentication failure that additionally carries a formatted WWW-Authenticate: Bearer ... challenge (CONTRACT.md §28.4 / §28.5 rule 4).

Derives from AuthError on purpose, mirroring AuthzChallengeError below it: an adapter that knows nothing about §28 still catches AuthError and returns the same 401 it always did; one that does catches this first (or dynamic_casts) and copies challenge() onto the response. The addition can never turn a failure into a different outcome.

Unlike AuthzChallengeError's UMA ticket, nothing here is sensitive (CONTRACT.md §28.8): the challenge names no credential, so — unlike the UMA challenge — it is fine to let it show up in what() and in a log line.
