884 // ---- §28.12 RFC 7592 client configuration (contract 1.53) ----
885 //
886 // A client that registered itself through `POST /oauth2/register` received,
887 // once, a `registration_client_uri` and a `registration_access_token`. With the
888 // two it reads, replaces and deletes ITS OWN registration. The four rules
889 // (§28.12.2) shape all three:
890 //
891 // 1. The URI is used verbatim — query included — and only at THIS client's
892 // base URL origin (scheme, host, port; http only for a loopback base). Any
893 // other is refused before any request with std::invalid_argument (C++'s
894 // local ValidationError mapping, §28.7), naming no part of the URI.
895 // 2. The token travels in `Authorization: Bearer` only.
896 // 3. It is not the SDK's session: no access token, no cookie (read or
897 // adopted), no CSRF or tenant header, no redirect followed, and a 401
898 // never reaches the §9 refresh guard.
899 // 4. Neither write is retried, on any status or transport error.
900 //
901 // A body with an `error` member is an OAuthProtocolError at any status (401
902 // `invalid_token`, 400 `invalid_client_metadata`, …); otherwise §2 by status.

944 // ---- §33 CIBA — client-initiated backchannel authentication (contract 1.58) ----
945 //
946 // A client that already knows whom it wants to authenticate asks AXIAM to
947 // authenticate that user ON ANOTHER DEVICE; AXIAM notifies the user, who
948 // approves or refuses on the console. The client collects the tokens at the
949 // token endpoint — by polling (ciba_await), or once after AXIAM pings it
950 // (ciba_handle_ping, then ciba_poll).
951 //
952 // The client ALWAYS authenticates (§33.1): client_secret_post with the
953 // configured oidc_client_secret(), or — a `tls_client_auth` client — the §6.1
954 // certificate with `client_id` alone in the form. A client built with neither
955 // is refused locally with AuthError, before any request. `tenant_id` goes in
956 // the query, never the body; X-Tenant-ID as for every /oauth2 call.
957 //
958 // Two things a caller must not read into a success:
959 // * A successful ciba_initiate() proves NOTHING about the user (§33.3 rule 4):
960 // AXIAM answers a hint naming nobody, a locked user and a real one
961 // identically; the only sign a user did not answer is `expired_token`.
962 // * A ping says the request was decided, never how (§33.2): the outcome —
963 // tokens, `access_denied` or `expired_token` — comes from ciba_poll().
964 //
965 // Ping mode: answer the ping 204 as soon as ciba_handle_ping() returns, THEN
966 // call ciba_poll() once (again at `interval` on `authorization_pending` /
967 // `slow_down`); if no ping has arrived after half of `expires_in`, fall back
968 // to ciba_await() (§33.7 rule 6) — a ping is at-least-once, never guaranteed.
