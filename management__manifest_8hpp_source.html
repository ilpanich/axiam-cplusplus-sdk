267// ---------------------------------------------------------------------------
268// §27.7's C++ declarative form: designated-initializer aggregate specs plus an
269// AXIAM_MANIFEST(...) macro.
270//
271// ManifestEntity is an aggregate whose every member carries a default member
272// initializer, which is what makes `.key = "x", .name = "y"` legal without
273// naming the members you do not care about — and, less obviously, what keeps
274// -Wextra quiet, since -Wmissing-field-initializers fires on an omitted member
275// only when that member has no default.
276//
277// The macros fix `.kind` and nothing else. They are sugar over the aggregate,
278// not a second way to build one: each expands to a ManifestEntity value and
279// AXIAM_MANIFEST expands to a Manifest holding them, so a manifest written this
280// way and one deserialized from configuration are the same value and go through
281// the same plan()/apply(). §27.7 requires exactly that — "a declarative form
282// that talks to the network itself is a second implementation of §27.6, and the
283// two will disagree."
284//
285// Designated initializers must appear in DECLARATION order, which for
286// ManifestEntity is: key, name, description, resource_type, action, is_global,
287// depends_on.
288//
289// const auto manifest = AXIAM_MANIFEST(
290// AXIAM_PERMISSION(.key = "read", .name = "documents:read", .action = "read"),
291// AXIAM_ROLE(.key = "editor", .name = "editor", .depends_on = "read"),
292// AXIAM_RESOURCE(.key = "root", .name = "documents", .resource_type = "folder"),
293// AXIAM_GROUP(.key = "editors", .name = "editors", .depends_on = "editor"));
294//
295// Unqualified in the axiam:: namespace on purpose: a macro has no namespace, so
296// the expansions below name their types fully instead.
297// ---------------------------------------------------------------------------
