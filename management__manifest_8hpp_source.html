385// ---------------------------------------------------------------------------
386// §27.7's C++ declarative form: designated-initializer aggregate specs plus an
387// AXIAM_MANIFEST(...) macro.
388//
389// ManifestEntity is an aggregate whose every member carries a default member
390// initializer, which is what makes `.key = "x", .name = "y"` legal without
391// naming the members you do not care about — and, less obviously, what keeps
392// -Wextra quiet, since -Wmissing-field-initializers fires on an omitted member
393// only when that member has no default.
394//
395// The macros fix `.kind` and nothing else. They are sugar over the aggregate,
396// not a second way to build one: each expands to a ManifestEntity value and
397// AXIAM_MANIFEST expands to a Manifest holding them, so a manifest written this
398// way and one deserialized from configuration are the same value and go through
399// the same plan()/apply(). §27.7 requires exactly that — "a declarative form
400// that talks to the network itself is a second implementation of §27.6, and the
401// two will disagree."
402//
403// Designated initializers must appear in DECLARATION order, which for
404// ManifestEntity is: key, name, description, resource_type, action, is_global,
405// depends_on.
406//
407// const auto manifest = AXIAM_MANIFEST(
408// AXIAM_PERMISSION(.key = "read", .name = "documents:read", .action = "read"),
409// AXIAM_ROLE(.key = "editor", .name = "editor", .depends_on = "read"),
410// AXIAM_RESOURCE(.key = "root", .name = "documents", .resource_type = "folder"),
411// AXIAM_GROUP(.key = "editors", .name = "editors", .depends_on = "editor"));
412//
413// Unqualified in the axiam:: namespace on purpose: a macro has no namespace, so
414// the expansions below name their types fully instead.
415// ---------------------------------------------------------------------------
